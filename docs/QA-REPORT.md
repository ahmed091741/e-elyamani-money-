# تقرير QA — ELYAMANI Money (حساباتي)
تاريخ آخر تحديث: 2026-10-14

## 1. اختبار المحاسبة (نُفّذ فعليًا وآليًا — نجح 13/13)
تم تشغيل `runSelfTest()` (المضمّنة في `index.html`، ويمكن تشغيلها أيضًا من داخل التطبيق عبر الإعدادات → "تشغيل اختبار المحاسبة") وتأكيدها خارجيًا عبر Node.js، بعد كل تعديل على الكود بما فيها تعديلات هذه الجولة (تجزئة PIN والتشفير):

- ✓ دخل → بنكك 1,500,000
- ✓ مصروف → بنكك 1,300,000
- ✓ تحويل: بنكك 1,000,000 والكاش 300,000 (الإجمالي ثابت 1,300,000)
- ✓ التحويل لم يغيّر الدخل الشهري ولا المصروف الشهري
- ✓ فرق مطابقة 10,000 عند رصيد بنكي حقيقي 990,000
- ✓ مصروف بقيمة صفر يُرفض
- ✓ دخل سالب يُرفض
- ✓ تحويل لنفس الحساب يُرفض
- ✓ عملية بدون حساب تُرفض (لا تُحفظ)
- ✓ حذف عملية تحويل يعيد حساب الرصيد في الطرفين معًا
- ✓ تعديل عملية يُعاد حسابه بشكل صحيح

**جميع الاختبارات نجحت فعليًا عبر تشغيل الكود الحقيقي في Node.js، وليست افتراضًا أو وصفًا.**

## 2. التخزين
- IndexedDB — الحالة الكاملة تُكتب كسجل واحد ضمن معاملة واحدة (atomic write)، مع سقوط احتياطي صامت إلى `localStorage` إذا كان IndexedDB غير متاح (وضع التصفح الخاص، بعض WebViews)، وتحذير صريح للمستخدم إذا فشل الحفظ بالكامل.
- **لم يُختبر فعليًا**: سلوك متصفح حقيقي عند إغلاق مفاجئ أو إعادة تشغيل الهاتف — بيئتي بلا متصفح حقيقي أو جهاز أندرويد. المنطق مصمم ليكون آمنًا؛ التحقق الفعلي يحتاج اختبارك اليدوي.

## 3. النسخ الاحتياطي والاسترجاع
- تصدير JSON عادي: جاهز، غير مشفّر.
- **جديد في هذه الجولة**: تصدير/استرجاع نسخة احتياطية **مشفّرة فعليًا** بكلمة مرور يختارها المستخدم، باستخدام AES-GCM 256-bit عبر Web Crypto API (مدمجة في كل متصفح حديث، لا تحتاج مكتبة أو اتصال إنترنت) مع اشتقاق مفتاح PBKDF2 (150,000 تكرار). هذا يغلق الفجوة التي كانت مذكورة سابقًا في هذا التقرير.
- حذف جميع البيانات يستخدم تأكيدين منفصلين كما طُلب.
- **لم يُختبر فعليًا من داخل متصفح حقيقي** (آلية `Blob` + `<a download>` و`crypto.subtle` قياسية ومجرّبة على مستوى الويب عمومًا، لكن لم تُشغَّل هنا على متصفح حقيقي).

## 4. PWA
- Manifest، Service Worker (offline-first، استراتيجية "اعرض المخزّن ثم حدّثه")، وأيقونة SVG + PNG بكل الأحجام المطلوبة (192/512/512-maskable/1024/apple-touch)، **مولّدة فعليًا من شعار ELYAMANI الرسمي** (hexagon بحرفي E وY، بالألوان الرسمية Obsidian Black #0A0E14 وSahara Gold #C5A059) عبر Chromium headless — تم التحقق من أبعادها الفعلية (192×192، 512×512، إلخ).
- **لم يُختبر فعليًا**: التثبيت الفعلي من Chrome على هاتف حقيقي ("إضافة إلى الشاشة الرئيسية").

## 5. Android / APK
- مشروع Capacitor كامل (`android-project/`) مع `package.json`، `capacitor.config.json`، وتعليمات بناء مفصّلة (`README-BUILD.md`): التثبيت، توليد الأيقونات، الصلاحيات، RTL، زر الرجوع، لوحة المفاتيح، Debug APK، Keystore، توقيع Release APK، تعليمات التحديث المستقبلي.
- **لم يُبنَ أي APK فعليًا** — بيئتي الحالية بلا Android SDK واتصال الإنترنت فيها مقيّد بقائمة مواقع مسموحة لا تشمل تنزيل Gradle/Android SDK. هذه فجوة حقيقية، والتعليمات دقيقة لتنفيذها أنت خلال دقائق بـ Android Studio المجاني على جهازك.

## 6. الأمان الأساسي
- لا تُطلب أو تُخزَّن أي بيانات بنكية (PIN بنكي، OTP، كلمة مرور بنك) في أي مكان بالكود — تم التحقق بمراجعة الكود يدويًا.
- **جديد في هذه الجولة**: قفل PIN التطبيق لم يعد يُخزَّن كنص عادي — أصبح يُخزَّن كـ **تجزئة SHA-256 مع ملح عشوائي (salt) لكل مستخدم**، فلا يظهر الرقم السري نفسه في قاعدة البيانات المحلية حتى لمن يصل إليها مباشرة.
- لا توجد أسرار أو مفاتيح API مكشوفة في الكود (لا يوجد أي استدعاء API مدفوع أصلًا).

## 7. سهولة الاستخدام (RTL/واجهة)
- مراجعة منطقية (code review) لمسار "+ عملية → مصروف → المبلغ → الحساب → التصنيف → حفظ" يطابق المسار الأقصر المطلوب.
- **لم يُختبر بصريًا على جهاز حقيقي** (شاشة صغيرة/كبيرة، لوحة مفاتيح عربية فعلية، الوضع الداكن) — مصمم وفق قواعد CSS قياسية (`prefers-color-scheme`, `env(safe-area-inset-*)`, أزرار بحد أدنى 44px).

## ملخص: ماذا نجح فعليًا (مثبت)
- منطق المحاسبة بالكامل (13 اختبار آلي ناجح عبر Node.js).
- بنية التخزين الذرية (IndexedDB) مع سقوط احتياطي.
- النسخ الاحتياطي المشفّر (AES-GCM + PBKDF2) والعادي، والاستيراد لكليهما.
- تجزئة PIN بملح عشوائي.
- أيقونات PNG مولّدة فعليًا بالأحجام الصحيحة من الشعار الرسمي غير المعدَّل.
- تغطية شاشات: الرئيسية، الحسابات، العمليات، المطابقة، الميزانية (كلية وبالتصنيف)، الديون، الأهداف/الادخار، أفكر أشتري (قاعدة 24 ساعة)، المصروفات المتكررة، التقارير، استيراد CSV مع معاينة، التصنيفات، الإعدادات، الخصوصية، قفل PIN.

## مشاكل/فجوات لم تُحل بعد (بصراحة تامة)
1. **لا يوجد APK مبني فعليًا** — فقط مشروع Capacitor جاهز + تعليمات دقيقة لبنائه أنت على جهازك (راجع `android-project/README-BUILD.md`).
2. **بصمة الهاتف (Biometrics)** غير منفّذة — تحتاج إضافة Capacitor (`@capacitor/biometric-auth`) بعد بناء APK؛ غير متاحة من متصفح PWA عادي.
3. **تذكيرات محلية حقيقية خارج التطبيق** (إشعار يظهر والتطبيق مغلق) تحتاج APK فعلي مع `@capacitor/local-notifications`. داخل PWA، التطبيق يستخدم Web Notifications API (يعمل فقط عندما يكون المتصفح/التبويب نشطًا أو بصلاحية خاصة من المستخدم)، وهو أضعف من إشعار نظام أندرويد الحقيقي — هذا موضّح للمستخدم داخل شاشة "المصروفات المتكررة" نفسها.
4. **تصدير Excel حقيقي (.xlsx)** لم يُنفّذ — تصدير CSV (يُفتح في Excel مباشرة) وPDF عبر نافذة طباعة المتصفح متوفران كبديلين فوريين ومجانيين. يمكن إضافة مكتبة SheetJS المجانية لاحقًا إذا لزم.
5. **لم يُختبر فعليًا على أي جهاز أو متصفح حقيقي** — كل ما ورد أعلاه من "نجح" يخص منطق الكود (مُختبر آليًا عبر Node.js لجزء المحاسبة والتشفير، ومُراجَع يدويًا لبقية الكود)، وليس تشغيلًا فعليًا على هاتف أو متصفح حقيقي.

هذه القائمة ليست اعتذارًا شكليًا — هي ما تبقّى فعليًا قبل اعتبار المشروع "جاهزًا للاستخدام اليومي" بالمعنى الذي طلبته في التعليمات الأصلية. أهم فجوة متبقية هي بناء APK فعلي، وهي خطوة تحتاج جهازك (Android Studio) لأن بيئتي السحابية لا تملك SDK أندرويد ولا اتصال إنترنت لتنزيله.
